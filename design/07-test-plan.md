# 07. 테스트 · 검증 계획

> 이 계산기의 유일한 실패 모드는 **틀린 숫자를 자신 있게 보여주는 것**입니다. UI 버그는 눈에 보이지만 계산 오류는 보이지 않습니다. 따라서 테스트 투자의 90%를 `src/calc/` 에 집중합니다.

---

## 1. 테스트 계층

| 계층 | 대상 | 도구 | 비중 |
|---|---|---|---|
| **골든 테스트** | 손계산·엑셀로 독립 검증된 값 | Vitest | 최우선 |
| **속성 테스트** | 무작위 입력에서 성립해야 하는 불변식 | Vitest + 자체 생성기 | 높음 |
| 단위 테스트 | 개별 함수 (경계값, 예외) | Vitest | 높음 |
| 회귀 스냅샷 | 대표 시나리오 결과 고정 | Vitest 스냅샷 | 중간 |
| 통합 테스트 | 입력 → 결과 파이프라인 | Vitest | 중간 |
| UI 테스트 | 포맷터, 입력 검증, URL 왕복 | Vitest + Testing Library | 낮음 |
| 접근성 감사 | 수동 + axe | — | M7에서 |

## 2. 골든 테스트 (`tests/golden/`)

아래 기대값은 **PowerShell로 독립 계산해 검증한 실제 값**입니다. 임의로 수정하지 마세요 (CLAUDE.md §5).

모든 골든 테스트는 룰셋 ID를 명시적으로 주입합니다: `getRuleSet('kr-2026')`.

### G-1. 적립식 복리 — 월초 납입 (기하 변환 검증)

```
입력: 초기 0원, 월 100만원, 연 총수익률 7%, 배당수익률 0%,
     10년(120개월), TER 0%, 세금 없음, 납입 시점 월초, 증액률 0%

기대: 172,018,882.61원   (허용 오차 ±1원)

검증식: FV = C × ((1+r)^n − 1)/r × (1+r),  r = 1.07^(1/12) − 1 = 0.0056541454
엑셀 대조: =FV(1.07^(1/12)-1, 120, -1000000, 0, 1)
```

### G-2. 적립식 복리 — 월말 납입

```
동일 조건, 납입 시점 월말
기대: 171,051,731.26원   (허용 오차 ±1원)
```
G-1 − G-2 = 967,151원. **월초/월말 구분이 실제로 결과를 바꾼다는 증거**이며, 원안 32행의 요구가 왜 중요한지 보여줍니다.

### G-3. 단순 나눗셈 변환 금지 검증 (음성 테스트)

```
동일 조건에서 월 수익률을 r/12 = 0.0058333 으로 계산하면
잘못된 값: 174,094,468.81원  (G-1보다 +2,075,586원 = +1.21%)

테스트: 엔진 결과가 174,094,468 에 가깝지 않음을 단정한다.
```
이 테스트는 누군가 `r/12` 로 "최적화"하는 것을 막습니다.

### G-4. 일시금 복리

```
입력: 초기 1억원, 추가납입 0, 연 7%, 30년, TER 0%, 세금 없음
기대: 761,225,504.27원   (= 1억 × 1.07^30)
```

### G-5. 물가 환산 (명목 → 실질)

```
입력: 명목 10억원, 물가 2%, 30년 후
기대: 552,070,888.98원   (비율 0.55207089 = 1/1.02^30)
```
원안 89~91행 요구의 직접 검증입니다.

### G-6. TER 차감 (자산 비례)

```
입력: 초기 1억원, 연 7%, 30년, TER 0.5%, 배당 0%
기대: 654,946,390.35원

검증: G-4 대비 비율 0.86038419 = 0.995^30
      → TER가 자산에 비례 차감되는 모델이 정확히 구현되었음을 의미
```
만약 `r − f = 6.5%` 로 계산하면 `1억 × 1.065^30 = 661,436,745원` 이 나옵니다. 이 값과 다름을 함께 단정합니다.

### G-7. 고정 실질 인출 — 정확한 소진

```
입력: 은퇴자산 10억원, 인출률 4%, 은퇴 후 명목수익률 = 물가상승률 (실질 0%)
     전략: 고정 실질 인출
기대: 정확히 25년 후 소진 (1e9 / 4e7 = 25)
     depletionAge = retirementAge + 25
```

### G-8. 계획 소진형 — 잔액 0 수렴

```
입력: 은퇴자산 10억원(실질), 은퇴 후 실질수익률 2%, 30년, annuity-due
기대: 연 인출액 43,774,433.62원 (월 3,647,869.47원)
     30년 후 잔액 ≈ 0 (허용 오차 ±1원)

검증식: PMT = A × rr / (1 − (1+rr)^−n) / (1+rr)
```

### G-9. Fisher 실질수익률

```
입력: 명목 7%, TER 0.15%, 물가 2%
기대: 보수 차감 후 명목수익률 = 6.839500%   (= 1.07 × 0.9985 − 1)
     실질 기대수익률       = 4.745098%   (= 1.0684 / 1.02 − 1)

음성 검증: 근사식 6.8395% − 2% = 4.8395% 와 다름을 단정
```
가정 패널에 표시되는 값이므로 정확해야 합니다.

### G-10. 배당 원천징수의 30년 누적 효과

```
입력: 초기 1억, 추가납입 0, 총수익률 7% (가격 5.5% + 배당 1.5%),
     30년, TER 0%, 배당 재투자 ON
케이스 A: 계좌 = ISA/연금 (배당 과세 없음)
케이스 B: 계좌 = 일반계좌 (배당 15.4% 원천징수)

기대: A > B 이고, 차이가 자산의 5% 이상
```
정확한 값은 구현 후 스냅샷으로 고정합니다. **이 테스트의 목적은 "ISA·연금계좌의 진짜 가치는 축적기 배당 비과세"라는 핵심 통찰이 계산에 실제로 반영되는지 확인**하는 것입니다 (03 문서 §2.2).

### G-11. 계좌 오버플로 배분

기본 우선순위는 `연금저축(세액공제 한도) → IRP(세액공제 한도) → ISA → 연금 추가 → 일반` 입니다 (02 문서 §2.1). ISA 연 한도가 4,000만원이므로 **연 4,800만원에서는 ISA가 잔여 전액을 흡수하고 연금 추가 납입은 발생하지 않습니다.**

```
입력: 월 400만원 (연 4,800만원), 우선순위 [연금저축, IRP, ISA, 일반]
기대 연 배분:
  연금저축 =  6,000,000원   (세액공제 한도)
  IRP     =  3,000,000원   (합산 세액공제 한도 900만원까지)
  ISA     = 39,000,000원   (잔여 전액, 연 한도 4,000만원 내)
  일반계좌 =         0원
  합계    = 48,000,000원   (정확히 일치)
```

2차 패스(연금 추가 납입, 합산 1,800만원까지)를 검증하려면 우선순위에서 ISA를 제외합니다.
```
입력: 월 400만원, 우선순위 [연금저축, IRP]
기대: 연금저축 + IRP = 18,000,000원 (합산 한도),  일반계좌 = 30,000,000원
```
합산 한도를 개별 한도로 잘못 처리하면 연금계좌에 3,600만원이 들어가 이 테스트가 깨집니다 (02 문서 §2.2의 함정).

ISA 누적 한도(2억원)도 함께 검증합니다: 이미 1.95억을 납입한 상태에서 4,000만원을 배분하면 ISA는 5,000만원이 아니라 **500만원**만 받고 나머지는 일반계좌로 넘어갑니다.

### G-12. 세액공제 환급금

```
입력: 연금저축 600만원 + IRP 300만원 납입, 총급여 5,500만원 초과
기대: 환급액 = 9,000,000 × 0.132 = 1,188,000원
     (총급여 5,500만원 이하면 9,000,000 × 0.165 = 1,485,000원)
     환급금은 다음 연도 납입에 가산
```

### G-13. 브리지 기간 제약

```
입력: 은퇴 나이 50세, 연금 개시 65세
기대: phases = ['브리지 1'(50~54), '브리지 2'(55~64), '연금 수령기'(65~)]
     50~54세 구간의 withdrawalByAccount에서 pensionSavings = 0, irp = 0
```
55세 제약이 강제되는지 확인합니다 (검토판 §2.4).

### G-14. Gross-up 역산 왕복

```
입력: 세후 필요액 5,000만원, 일반계좌 (해외상장 ETF, 차익비율 60%)
기대: solveGross() 결과 g 에 대해
     netAfterTaxAndInsurance(g) ≈ 50,000,000  (허용 오차 ±1,000원)
```
역산의 정확성은 왕복 검증으로만 확인할 수 있습니다.

### G-15. Monte Carlo 재현성

```
입력: 동일 입력, 동일 시드(42), 2회 실행
기대: 두 결과가 완전히 동일 (successRate, 모든 백분위 경로)
```

`Math.random()` 사용을 잡아내는 테스트입니다 (ADR-5).

```
입력: 변동성 σ = 0.0001 (거의 0), 시행 1,000회
기대: 중위 최종자산 ≈ 결정론적 계산 결과 (오차 1% 이내)
```

## 3. 속성 테스트 (`tests/property/`)

무작위 입력 500세트에 대해 아래 불변식이 항상 성립해야 합니다. 생성기는 유효 범위 내에서 샘플링합니다.

| # | 불변식 |
|---|---|
| P-1 | **보수 차감 후** 수익률 ≥ 0 이면 `finalBalance ≥ totalPrincipal` |
| P-2 | 총수익률을 올리면 `finalBalance` 단조 증가 |
| P-3 | TER를 올리면 `finalBalance` 단조 감소 |
| P-4 | 물가상승률을 올리면 `finalBalance.real` 단조 감소 |
| P-5 | 물가상승률은 `finalBalance.nominal` 에 영향을 주지 않음 (수익률과 독립) |
| P-6 | 과세 계좌 결과 ≤ 동일 조건 비과세 계좌 결과 |
| P-7 | 인출률을 올리면 `depletionAge` 가 같거나 앞당겨짐 |
| P-8 | 고정 비율 인출(`fixedPercent`)은 절대 고갈되지 않음 (`depletionAge === null`) |
| P-9 | 계좌 배분 합계 = 총 납입액 (오차 0원, 부동소수 허용 오차 0.01원) |
| P-10 | 월 납입액을 올리면 달성률 단조 증가 |
| P-11 | `finalBalance.real × (1+i)^Y ≈ finalBalance.nominal` (오차 0.001%) |
| P-12 | 모든 금액 출력이 유한값 (`Number.isFinite`) — `NaN`/`Infinity` 없음 |
| P-13 | `costBasis ≤ balance` (**가격상승분이 보수를 상회**하는 조건에서: `(1+p)(1−f) ≥ 1`) |
| P-14 | 은퇴 나이를 늦추면 `finalBalance` 단조 증가 |
| P-15 | 솔버 결과를 입력에 대입하면 달성률 ≈ 100% (오차 0.5%) |

**P-12가 가장 중요합니다.** `NaN` 은 조용히 전파되어 화면에 `NaN원` 으로 나타나거나, 더 나쁘게는 비교 연산에서 `false` 를 반환해 잘못된 판정을 만듭니다.

**P-1 · P-13의 조건 정정 (구현 검증 중 발견):** 두 불변식이 `총수익률 ≥ 0` 조건에서 실패했습니다. 원인은 계산 오류가 아니라 불변식 진술의 부정확함이었습니다.

- **P-1**: TER가 총수익률보다 크면 순수익률 `(1+r)(1−f)−1` 이 음수가 되어 원금이 잠식되는 것이 **정상**입니다(예: 총수익률 0.5%, TER 1%). 조건을 `netNominalReturn(r, f) ≥ 0` 으로 정정했습니다.
- **P-13**: 평가이익이 생기려면 **가격상승분이 보수를 상회**해야 합니다. 재투자된 배당은 전액 취득원가에 가산되므로 배당이 커도 평가이익을 만들지 않습니다. 따라서 `(1+p)(1−f) ≥ 1` 이 정확한 조건입니다. 총수익률이 양수여도 가격상승분이 보수보다 작으면 평가손실이 남는 것이 정상입니다.

두 경우 모두 반대 방향(보수가 수익률을 잠식하는 경우)을 별도 테스트로 명시해 동작을 고정했습니다.

**고갈(depletion) 판정의 정정:** `depletionAge` 는 자산이 0이 된 나이를 그대로 보고하지만, 계획 소진형·VPW 전략은 **종료 나이에 잔액 0이 되는 것이 설계 의도**이므로 경고를 띄우지 않습니다. `ASSET_DEPLETION` 경고는 `depletionAge < endAge` 인 조기 고갈에만 발생합니다.

### 단조성 위반 처리
세금 공제 구간(해외상장 ETF 250만원 공제)과 계좌 한도 때문에 미세한 비단조 구간이 실제로 존재할 수 있습니다. 이 경우 테스트를 완화하는 대신 **허용 오차를 명시**하고(예: 0.1% 이내 역전 허용) 원인을 주석에 기록합니다. 원인을 모른 채 테스트를 느슨하게 만들지 않습니다.

## 4. 단위 테스트 필수 항목

### `rates.ts`
- `r = -0.99`, `r = 0`, `r = 0.20` 경계
- `i = 0` 일 때 명목 = 실질
- `f = 0` 일 때 `monthlyFeeFactor = 1`

### `allocate.ts`
- 납입액 0
- 우선순위 목록이 비어있음 → 전액 일반계좌
- ISA 누적 한도(2억원) 도달 후 오버플로
- 수동 배분 모드에서 합계가 총액과 불일치 → 검증 오류

### `withdraw.ts`
- 은퇴 나이 = 종료 나이 (기간 1년)
- 자산 0으로 은퇴 → 즉시 고갈, 예외 없이 결과 반환
- `rr ≈ 0` 폴백 경로 (전략 ③④)
- 연금소득만으로 생활비가 충족되는 경우 → 인출액 0
- 연금수령한도 초과 시 기타소득세 적용

### `tax/withdrawal.ts`
- 차익 비율 0% (전액 원금) → 세금 0
- 해외상장 ETF 연 250만원 공제가 연 1회만 적용
- 국내상장 해외ETF에 250만원 공제가 **적용되지 않음** (혼동 방지 테스트)
- 사적연금 연 1,500만원 경계 (1,499만 / 1,501만)
- 연금소득세율 연령 경계 (69/70세, 79/80세)

### `solve.ts`
- 해가 없는 경우 `null` 반환 (달성 불가능한 목표)
- 이미 목표를 초과 달성한 경우 (필요 납입액 0)
- `maxIter` 도달

### `lib/format.ts`
| 입력 | 기대 |
|---|---|
| `0` | `'0원'` |
| `9_999` | `'9,999원'` |
| `10_000` | `'1만원'` |
| `3_000_000` | `'300만원'` |
| `99_999_999` | `'9,999만원'` |
| `100_000_000` | `'1억원'` |

| `1_000_000_000_000` | `'1조원'` (또는 `'10,000억원'` — 구현 시 확정) |

### `lib/url-codec.ts`
- 왕복: `decode(encode(input))` === `input` (깊은 동등)
- 기본값과 동일한 필드는 인코딩에서 제외되고 복원 시 기본값으로 채워짐
- 손상된 문자열 → 예외 없이 기본값 폴백
- `CompressionStream` 미지원 폴백 경로

### `lib/schema.ts`
- `retirementAge <= currentAge` → 검증 실패
- `dividendYield > totalReturn` → 검증 실패
- 미래 `schemaVersion` → 폴백 (마이그레이션 없음)
- 문자열로 저장된 숫자 → 파싱 실패 시 기본값

## 5. 회귀 스냅샷 (`tests/snapshots/`)

대표 시나리오 5개의 전체 결과를 스냅샷으로 고정합니다. 리팩터링 시 의도치 않은 숫자 변경을 잡습니다.

| # | 시나리오 |
|---|---|
| S-1 | 기본값 그대로 (35세 → 55세 은퇴, 월 100만원, 7%, 목표 300만원) |
| S-2 | 조기 은퇴 (30세 → 45세, 월 300만원, 브리지 기간 25년) |
| S-3 | 늦은 시작 (50세 → 65세, 월 200만원, 초기 자산 3억) |

## 6. 세제 데이터 검증

`src/data/tax/*.ts` 에 대한 구조 테스트입니다.

| 테스트 | 내용 |
|---|---|
| D-1 | 모든 `Sourced<T>` 항목에 `source`, `asOf`, `status` 가 존재 |
| D-2 | 모든 `source` 가 유효한 URL 형식 |
| D-3 | 모든 `asOf` 가 `YYYY-MM-DD` 형식이며 미래 날짜가 아님 |
| D-4 | `status: 'proposed'` 항목이 `proposed` 블록에만 존재 |
| D-5 | 세율이 0~1 범위 (퍼센트 정수를 실수로 넣는 실수 방지 — `15.4` vs `0.154`) |
| D-6 | 한도 금액이 양수이고 상식적 범위 (1만~10억) |
| D-7 | 연금저축 세액공제 한도 ≤ 합산 세액공제 한도 ≤ 합산 납입한도 |
| D-8 | ISA 연 한도 ≤ 총 한도 |
| D-9 | 연금소득세율이 연령 증가에 따라 단조 감소 |
| D-10 | `applyProposed()` 가 원본 룰셋을 변형하지 않음 (불변성) |

**D-5는 실제로 발생하기 쉬운 버그입니다.** `0.154` 대신 `15.4` 를 넣으면 세금이 1,540%가 되어 자산이 음수로 갑니다.

## 7. 수동 검증 체크리스트 (릴리스 전)

계산 결과의 **타당성**은 자동 테스트로 완전히 검증할 수 없습니다. 릴리스 전 사람이 확인합니다.

| # | 확인 항목 |
|---|---|
| M-1 | 기본값으로 나온 결과가 상식적인가? (35세 월 100만원 20년 → 은퇴자산 5~7억 수준) |
| M-2 | 물가상승률을 0%로 두면 명목 = 실질인가? |
| M-3 | 수익률을 0%로 두면 최종자산 = 납입원금인가? |
| M-4 | 세금을 모두 0으로 오버라이드하면 계좌 유형별 결과가 동일한가? |
| M-5 | 슬라이더를 극단으로 움직여도 화면이 깨지거나 `NaN` 이 보이지 않는가? |
| M-6 | 가정 패널의 모든 `출처↗` 링크가 실제로 열리는가? |
| M-7 | 가정 패널의 모든 값이 실제 계산에 쓰인 값과 일치하는가? (하드코딩된 표시값 없음) |
| M-8 | 세제 기준일이 푸터에 표시되고 룰셋과 일치하는가? |
| M-9 | 국민연금 조회 링크가 공단 페이지로 연결되는가? |
| M-10 | URL 공유 후 다른 브라우저에서 열었을 때 동일한 결과가 나오는가? |
| M-11 | 개발자 도구 Network 탭에 어떤 요청도 발생하지 않는가? (프라이버시 원칙 검증) |
| M-12 | 모바일에서 핵심 지표가 스크롤 없이 보이는가? |
| M-13 | 다크 모드에서 차트가 읽히는가? |
| M-14 | 200% 확대에서 레이아웃이 유지되는가? |
| M-15 | 키보드만으로 모든 입력을 조작할 수 있는가? (우선순위 드래그 포함) |

**M-11이 특히 중요합니다.** 프라이버시 원칙은 코드 리뷰만으로는 보장되지 않으며, 실제 Network 탭 확인이 유일한 증거입니다.

## 8. 커버리지 목표

| 영역 | 목표 |
|---|---|
| `src/calc/**` | 라인 95% / 분기 90% |
| `src/data/**` | 구조 테스트 100% 통과 |
| `src/lib/**` | 라인 90% |
| `src/components/**`, `src/features/**` | 목표 없음 (수동 검증 + 스냅샷) |

UI 커버리지를 강제하지 않습니다. 계산 엔진에 집중된 투자가 이 제품에서 훨씬 높은 가치를 냅니다.
