### 입력 밀도: 간단 / 자세히 (2026-08-08 추가)

위 목업은 **자세히 모드**입니다. 입력 패널에는 컨트롤이 40개 넘게 있고 라벨의 절반이 업계 용어(`Total Return`, `TER`, `안전인출률`, `배분 우선순위`)입니다. 금융 배경이 없는 사용자에게 이 화면은 **첫 화면에서 이탈하는 화면**입니다.

그래서 입력 패널 최상단에 밀도 전환을 둡니다. 기본값은 **간단**입니다.

```
┌─────────────────────────────┐
│  간단  │  자세히             │  ← 세그먼티드
├─────────────────────────────┤
│ 지금 나이        [ 35 ]세    │
│ 은퇴하고 싶은 나이 [ 55 ]세   │
│ 지금까지 모은 돈  [ 0원 ]     │
│ 매달 투자할 돈    [ 100만원 ] │
│ 은퇴 후 매달 쓸 돈 [ 300만원 ]│
├─────────────────────────────┤
│ ⓘ 나머지는 이 가정을 씁니다:  │
│   수익률 7% · 물가 2% ...    │
│   [자세히 설정에서 바꾸기]    │
└─────────────────────────────┘
```

**간단 모드에 넣는 5가지의 기준**: 사용자만 알 수 있고 기본값을 대신 정해줄 수 없는 값. 나머지는 전부 `DEFAULT_INPUT` 에 근거 있는 보수적 기본값이 있으므로 묻지 않습니다.

규칙:

1. **간단 모드는 계산을 바꾸지 않습니다.** 노출되는 입력의 개수만 다르고, 숨겨진 값은 전부 기본값 그대로 계산에 들어갑니다. 두 모드가 같은 `CalculatorInput` 을 공유하므로 전환해도 값이 유지됩니다.
2. **모드는 `CalculatorInput` 에 넣지 않습니다.** 공유 링크·저장 데이터에 담기면 상대방의 화면 선호까지 덮어씁니다. 별도 스토어(`src/store/inputMode.ts`)에서 `localStorage` 로만 관리합니다.
3. **R-8(근거 노출)은 간단 모드에서도 지켜집니다.** 숨긴 가정을 요약 문구로 항상 보여주고, 자세히 모드로 가는 버튼을 함께 둡니다. 가정 패널은 결과 쪽에 그대로 있습니다.
4. **"지금까지 모은 돈"은 계좌 합계입니다.** 계좌 구분이 없으면 전액 일반계좌로 넣습니다 — 과세가 가장 불리한 계좌이므로 과대추정을 만들지 않습니다. 이미 계좌를 나눠둔 사용자는 그 비율이 유지됩니다(합계를 바꾸면 비례 조정).

   다만 **보수적 배치는 틀린 배치이기도 합니다.** 연금저축·ISA에 이미 목돈이 있는 사용자는 세금이 과다 계산돼 결과가 낮게 나옵니다. 그래서 간단 모드에도 `계좌별로 나눠 입력하기` 접이식을 두고, **비(非)일반계좌 잔액이 이미 있으면 펼친 상태로 시작**합니다 — 접힌 채로 두면 사용자가 잘못 계산된 줄 모릅니다. 이 접이식은 간단 모드의 "5가지" 원칙에 대한 의도된 예외입니다.
5. **숨은 필드에 검증 오류가 생기면 간단 모드에서 알립니다.** (예: 은퇴 나이 > 자산 사용 종료 나이) 오류를 화면 밖에 둔 채로 두지 않습니다.

### 모바일 (<768px)

단일 컬럼. 순서: **핵심 지표(sticky 요약 바) → 입력 아코디언 → 그래프 → 표들 → 가정 패널**

입력을 조작하는 동안 화면 상단에 축소된 핵심 지표 바가 고정되어, 슬라이더를 움직이며 숫자가 변하는 것을 즉시 볼 수 있게 합니다. 이것이 이 계산기의 가장 중요한 인터랙션입니다.

```
┌─────────────────────────┐
│ 월 287만원 ↑ · 달성 95.7%│ ← sticky
├─────────────────────────┤
│ ▼ ① 기본 정보            │
│  ...                    │
```

## 3. 핵심 지표 카드 (순서 고정)

| 순위 | 지표 | 시각 위계 |
|---|---|---|
| 1 | **지금 계획대로면 은퇴 후 월 사용 가능액 (오늘 구매력, 세후)** | 전체 폭, 40px+ 숫자 |
| 2 | 목표 달성률 + **부족액(월 금액)** | 게이지 + 퍼센트 |
| 3 | 예상 은퇴자산 (부채 차감 후, 명목 / 오늘가치) | 2줄 |
| 4 | 총납입원금 / 투자수익 | 비중 바 |
| 5 | **목표를 채우는 방법** (필요 총자산 · 필요 월 납입액 + 적용 버튼) | 패널, 제목 크기 숫자 |

### 두 질문을 한 화면에서 다루는 방식 (2026-08-09 결정)

사용자가 지적한 개념 충돌입니다. 이 계산기에는 정반대 방향의 두 질문이 있습니다.

- **정방향** — 매달 ○○원 넣으면 노후에 얼마 받나?
- **역방향** — 노후에 ○○원 쓰려면 얼마를 모으고 매달 얼마 넣어야 하나?

나이·기간·수익률이 정해지면 **목표 생활비와 월 납입액 중 하나만 자유롭게 정할 수 있습니다.** 둘 다 입력받으면 과결정(over-determined)이고, 그 모순을 봉합하려고 생긴 개념이 달성률입니다. 결과 화면에 두 답("130만원 받습니다" / "245만원 넣어야 합니다")이 같은 크기로 나란히 놓이면 사용자는 무엇이 답인지 알 수 없습니다.

**채택하지 않은 안**

- *탭으로 분리*: 두 질문은 대안이 아니라 한 생각의 연속된 단계입니다("지금대로면? → 부족하네, 얼마 넣지? → 무리다, 은퇴를 늦추면?"). 탭은 이 흐름 한가운데서 화면 이동을 강제하고, 입력의 90%가 공유되므로 값이 유지되는지 불안하게 만듭니다.
- *납입액 입력칸 잠금*: 모드에 따라 입력칸이 읽기 전용으로 바뀌면 사람 경험으로 이상합니다. **어떤 입력도 잠그지 않습니다.**

**채택한 안 — 하나의 답 + 종속된 처방**

화면은 위에서 아래로 하나의 문장을 이룹니다: **지금 계획의 결과 → 목표와의 차이 → 차이를 메우는 방법.**

1. 히어로는 **화면에서 유일한 큰 숫자**이고 정방향 답만 담습니다. 라벨에 "지금 계획대로면"을 붙여 조건부임을 명시합니다.
2. 달성률 옆에 **부족액을 금액으로** 함께 줍니다 — 퍼센트만으로는 크기가 잡히지 않습니다.
3. 역방향 답(필요 총자산·필요 월 납입액)은 ②~④ **뒤에** 두고 숫자 크기를 한 단계 낮춥니다. 히어로와 경쟁하는 답이 아니라 ②의 차이를 메우는 처방이기 때문입니다. 패널 제목이 그 관계를 말합니다("목표 월 300만원을 채우려면").
4. 필요 총자산 옆에 **지금 계획대로 모이는 돈**을 나란히 둡니다. 두 숫자의 차이가 곧 부족분입니다.

세부 규칙:

- 목표를 이미 넘겼다면 제목이 "목표를 넘었습니다"로 바뀌고 여유액을 알려줍니다 — 과납입도 정보입니다.
- **버튼 뒤에 두지 않습니다.** 이분법 1회는 실측 약 4ms(전체 시뮬레이션 ≈1ms × 16회)라 입력이 바뀔 때마다 자동 갱신해도 됩니다. 나머지 역산(필요 수익률·가장 이른 은퇴 나이)은 비용이 커서 `역산 도구` 섹션에 남기고, 이 패널에서 그쪽을 안내합니다.
- **표시·적용 금액은 만원 단위로 올림합니다.** `formatKRW` 는 버림이라 2,449,417원을 "244만원"으로 보여주는데, 그 금액을 그대로 적용하면 목표에 미달합니다. 보여준 금액을 넣으면 반드시 목표가 채워져야 합니다.

카드 1의 부기 텍스트:
```
287만원  ← 오늘 구매력 기준
명목 512만원 · 세금 34만원 · 건강보험료 12만원 차감 후
```
**세금과 건보료를 명시적으로 보여주는 것**이 이 계산기의 차별점입니다. 숨기지 않습니다.

달성률 게이지 색상:
- ≥100%: 초록 / 80~99%: 노랑 / <80%: 주황 (빨강은 쓰지 않음 — 사용자를 겁주는 것이 목적이 아님)
- 필요 월 납입액은 게이지 옆이 아니라 **지표 1.5 로 승격**해 표시합니다 (위 참고)

## 4. 자산 성장 그래프 (원안 149~157행)

### 스펙

| 항목 | 값 |
|---|---|
| 유형 | 누적 면적 + 라인 조합 (Recharts `ComposedChart`) |
| X축 | 나이 (토글: 연도) — 현재 나이 ~ 종료 나이 **전 생애** |
| Y축 | 금액. 억원 단위 축약 (`5억`, `10억`) |
| 시리즈 1 | 누적 납입원금 — 면적, 채도 낮은 색 |
| 시리즈 2 | 투자수익 — 면적, 시리즈 1 위에 누적 |
| 시리즈 3 | 총자산 — 라인, 굵게 (= 1+2, 인출기에는 감소) |
| 기준선 | 은퇴 나이 수직선 + `은퇴 55세` 라벨 |
| 기준선 | 국민연금 개시 나이 수직선 (점선) |
| 기준선 | 목표 필요자산 수평선 (점선) |
| 토글 | 명목 ↔ 실질 |
| 마커 | 자산 고갈 나이 (있을 때) — X 마커 + 라벨 |
| 툴팁 | 해당 나이의 자산(명목/실질), 원금, 수익, 그 해 인출액 |

### 구현 시 확정한 세부 사항

브라우저 검증에서 드러난 두 가지를 반영했습니다.

1. **X축은 category 가 아니라 숫자 축**(`type="number"`, `domain=['dataMin','dataMax']`)을 씁니다. category 축을 쓰면 기준선(은퇴·연금 개시)이 인덱스 위치에 놓여 실제 나이와 어긋납니다.
2. **인출기 구간의 원금/수익 값은 `0` 이 아니라 `null`** 입니다. `0` 을 넣으면 은퇴 시점의 급락 구간에서 monotone 보간이 오버슈트해 톱니 형태의 허상이 생깁니다. 면적 시리즈는 `type="linear"` + `connectNulls={false}` 로 은퇴 시점에서 깔끔히 끝납니다.
3. 축적기 마지막 스냅샷과 인출기 첫 행은 나이가 같으므로(둘 다 은퇴 나이) 차트에서는 중복 지점을 만들지 않습니다. 인출기 값은 **연말 잔액 기준**이며, 정확한 연도별 값은 상세 표·CSV로 제공합니다.

### 인출기를 같은 차트에 그리는 이유
축적기만 보여주면 "10억을 모았다"에서 끝납니다. 은퇴 후 자산이 어떻게 감소하는지(혹은 유지되는지)를 **같은 화면에서 연결해 보여줄 때** 사용자가 계획의 지속성을 이해합니다. 이 차트가 제품의 핵심 시각 산출물입니다.

### 3시나리오 모드 (M5)
기준 시나리오를 실선으로, 보수/낙관을 반투명 밴드로 겹칩니다. 시리즈가 많아지므로 이 모드에서는 원금/수익 분해 면적을 숨깁니다.

### Monte Carlo 모드 (M6)

## 9. 금액 표기 (`src/lib/format.ts`)

한국 사용자는 `1,234,560,000` 을 즉시 읽지 못합니다. 억/만원 단위가 필수입니다.

```ts
formatKRW(1_234_560_000)            // '12억 3,456만원'
formatKRW(3_000_000)                // '300만원'
formatKRW(1_234_560_000, 'compact') // '12.3억'
formatKRW(0)                        // '0원'
formatKRW(-5_000_000)               // '-500만원'
formatKRW(1_200_000_000, 'exact')   // '1,200,000,000원'  (연도별 표·CSV용)
```

규칙:
- 1억 이상: `N억 M,MMM만원` (만원 미만 절사, 절사했음을 툴팁으로 표시하지 않음 — 노이즈)
- 1만 이상 1억 미만: `N,NNN만원`
- 1만 미만: `N,NNN원`
- `compact` 모드: 차트 축·좁은 카드용 (`12.3억`)
- `exact` 모드: 상세 표·CSV용
- 음수는 `-` 접두. 회계식 괄호 표기는 쓰지 않음

퍼센트: 소수 둘째 자리까지 (`7.00%`, `0.15%`). 입력 필드에서는 사용자가 `7` 을 치면 7%로 해석.

**입력 중 힌트:** 금액 입력 필드 아래에 실시간으로 `→ 300만원` 을 표시해 오타(0 하나 차이)를 즉시 알아채게 합니다. 금융 계산기에서 가장 흔한 사용자 실수입니다.

## 10. 입력 컴포넌트 규약

| 필드 유형 | 컴포넌트 | 비고 |
|---|---|---|
| 금액 | 숫자 입력 + 단위 힌트 + 프리셋 칩 | 프리셋: `50만` `100만` `200만` `300만` |
| 비율 | 슬라이더 + 숫자 입력 | 슬라이더는 상용 범위, 숫자 입력은 전체 범위 |
| 나이 | 숫자 입력 (스테퍼) | |
| 선택 | 세그먼티드 컨트롤 (2~3개) / 셀렉트 (4개+) | |
| 우선순위 | 드래그 정렬 목록 + 키보드 대체 조작 | 키보드로도 순서 변경 가능해야 함 |
| 토글 | 스위치 + 설명 텍스트 | |

**슬라이더는 반드시 숫자 입력과 함께** 제공합니다. 슬라이더만 있으면 정확한 값을 넣을 수 없고, 숫자 입력만 있으면 탐색적 조작이 어렵습니다.

## 11. 접근성

| 항목 | 요구 |
|---|---|
| 키보드 | 모든 조작 가능. 드래그 정렬은 `↑/↓` + 수정자 키 대체 경로 제공 |
| 포커스 | 가시적 포커스 링. 커스텀 컴포넌트도 예외 없음 |
| 스크린리더 | 핵심 지표는 `aria-live="polite"` — 입력 변경 시 새 값 안내 |
| 차트 | `role="img"` + `aria-label` 요약. 동일 데이터를 표로도 제공 (연도별 표) |
| 색상 | 대비 4.5:1 이상. 색약 대응 팔레트. **색 외에 레이블·패턴으로도 구분** |
| 확대 | 200% 확대에서 레이아웃 붕괴 없음 |
| 애니메이션 | `prefers-reduced-motion` 존중 |
| 다크 모드 | 시스템 설정 + 수동 토글. 차트 색상도 테마별 정의 |

차트에서 "원금은 파란색, 수익은 초록색"만으로 구분하지 않고, 항상 직접 레이블 또는 패턴을 함께 씁니다.
