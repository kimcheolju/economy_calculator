# 08. 디자인 시스템 — 톤앤매너 지침

이 문서는 **시각 언어**를 규정합니다. 정보구조·동작·카피는 `05-ui-ux.md` 가 계속 담당하며, 두 문서는 충돌하지 않습니다.

- `05-ui-ux.md` → 무엇을 어떤 순서로 보여주는가, 어떻게 동작하는가, 뭐라고 쓰는가
- **`08-design-system.md`(이 문서)** → 그것을 어떤 색·크기·간격·형태로 그리는가

새 화면·컴포넌트를 만들기 전에 이 문서를 읽으세요. 여기서 벗어나야 한다면 **먼저 이 문서를 고치고** 이유를 남깁니다 (CLAUDE.md §9).

---

## 1. 방향

**금융 프로덕트.** Linear·Stripe 계열의 도구 미감입니다.

| 지향 | 지양 |
|---|---|
| 뉴트럴 기반 + 액센트 1색 | 알록달록한 다색 UI |
| 여백과 잉크 농도로 만드는 위계 | 크기만 키워서 만드는 위계 |
| 최소한의 hairline 경계 | 모든 것을 감싼 테두리 카드 |
| 숫자가 화면의 주인공 | 라벨·장식이 숫자만큼 진한 화면 |
| 조용한 상태 표현 | 겁주는 빨강·경고 아이콘 남용 |

한 문장으로: **"전문가가 매일 쓰는 도구"처럼 보여야 하고, "예쁘게 꾸민 랜딩페이지"처럼 보이면 안 됩니다.**

## 2. 원칙

### P-1. 위계는 크기가 아니라 잉크·여백이 만든다
글자 크기를 키우는 것은 마지막 수단입니다. 먼저 `--ink` / `--ink-secondary` / `--ink-muted` 3단계와 여백으로 구분하세요.
화면 전체에서 **히어로 크기(`text-hero`)를 쓰는 값은 단 하나** — "은퇴 후 매달 쓸 수 있는 돈"뿐입니다.

### P-2. 테두리보다 여백
구획은 여백이 나눕니다. 그래도 경계가 필요하면 hairline(`border-rule`) 하나. 카드를 중첩하지 마세요 — 테두리가 두 겹이 되면 `FieldGroup`(배경만 눌러 구분)을 씁니다.

### P-3. 액센트는 아껴 쓴다
`--accent` 는 **한 화면에 몇 군데만**. primary 버튼은 화면당 하나입니다. 선택 상태는 액센트로 꽉 채우는 대신 표면 위로 살짝 띄웁니다(`bg-surface` + `shadow-raised` on `bg-surface-sunken`).

### P-4. 색은 단독으로 의미를 지지 않는다
상태·계열·선택 여부는 항상 **아이콘 또는 레이블**과 함께 갑니다. 색약 사용자, 흑백 인쇄, `forced-colors` 에서도 읽혀야 합니다.
표에서 선택된 행은 배경색 + `현재` 배지, 경고는 배경색 + 아이콘, 차트 계열은 색 + 범례.

### P-5. 그림자는 떠 있는 것에만
`--shadow-raised` 는 세그먼트 컨트롤의 활성 칩과 토글 손잡이 정도. `--shadow-overlay` 는 팝오버·드롭다운 전용. **패널·카드에는 그림자를 쓰지 않습니다.**

정의 위치는 `src/index.css` 한 곳뿐입니다. 컴포넌트에서 hex 를 직접 쓰지 마세요.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `--plane` | `#f9f9f7` | `#0d0d0d` | 페이지 바닥 |
| `--surface` | `#fcfcfb` | `#1a1a19` | 패널·카드 |
| `--surface-sunken` | `#f2f1ed` | `#121211` | 트랙·눌린 영역·하위 그룹 |
| `--ink` | `#0b0b0b` | `#ffffff` | 값, 제목 |
| `--ink-secondary` | `#52514e` | `#c3c2b7` | 라벨, 본문 |
| `--ink-muted` | `#898781` | `#898781` | 부기, 축 눈금, 비활성 |

### 3.3 상태색 (예약 — 시리즈로 재사용 금지)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--good` | `#0ca30c` | 달성률 100% 이상 |
| `--warning` | `#fab219` | 경고 배지, SORR 블록 |
| `--serious` | `#ec835a` | 달성률 80% 미만 |
| `--critical` | `#d03b3b` | 입력 오류, 실행 실패 |
| `--success-text` | `#006300` / `#0ca30c` | 성공 **텍스트** |

빨강(`--critical`)은 **차단성 오류에만** 씁니다. 목표 미달은 오류가 아닙니다 (05-ui-ux.md §13).

### 3.4 타이포

| 토큰 | 크기 | 용도 |
|---|---|---|
| `text-hero` | `clamp(2.25rem, 7vw, 3.25rem)` | 화면당 1회 — 월 사용 가능액 |
| `text-metric-lg` / `text-metric` | 2rem / 1.5rem | 지표 값 |
| `text-title` | 1rem | 지표 값(작은 것), 소제목 |
| `text-body` | 0.875rem | 본문, 패널 제목 |
| `text-caption` | 0.75rem | 라벨, 표 셀 |
| `text-micro` | 0.6875rem | 부기, 표 머리, 축 |

**임의 크기를 새로 만들지 마세요.** `text-xs` / `text-sm` / `text-base` 같은 Tailwind 기본 크기도 쓰지 않습니다 — 스케일이 두 벌이 됩니다.

폰트는 시스템 산세 단일입니다. 외부 폰트·CDN 금지 (CLAUDE.md R-7).

### 3.5 숫자 표기

`.numeric` 클래스(= `tabular-nums`)는 **세로로 정렬되어야 하는 숫자**에 씁니다: 표 열, 축 눈금, 그리고 **입력 조작 중 실시간으로 바뀌는 지표**.

> dataviz 기본 규칙은 히어로 숫자에 비례 숫자를 권하지만, 그 규칙은 정적인 숫자를 전제합니다. 이 계산기의 히어로 값은 슬라이더를 드래그하는 동안 매 틱 갱신되므로, 비례 숫자를 쓰면 자릿수 폭이 흔들려 읽는 도중 시선이 튑니다. **의도적 예외이며 근거는 이 문단입니다.**

### 3.6 라운드·레이어

`--radius-control` (6px) = 버튼·입력·칩 / `--radius-panel` (10px) = 패널·팝오버.
그림자는 P-5 참조.

## 4. 색을 바꾸는 절차 (필수)

팔레트는 눈으로 고른 것이 아니라 **검증을 통과시킨 값**입니다. 출처는 dataviz 스킬의 레퍼런스 인스턴스이며, 이 앱의 실제 표면(`#fcfcfb` / `#1a1a19`)에 대해 재검증했습니다.

```
라이트 all-pairs — CVD ΔE 9.2 · 일반시야 ΔE 24.0 · PASS
다크   all-pairs — CVD ΔE 9.4 · 일반시야 ΔE 20.9 · PASS
```

라이트 모드에서 `--series-3`(aqua)만 표면 대비 **2.74:1 로 WARN** 입니다. 이 경고는 무시 대상이 아니라 **"가시적 레이블 또는 표 뷰 제공" 의무**를 지웁니다 — 범례·직접 레이블과 연도별 상세 표로 충족합니다 (05-ui-ux.md §11). 이 구제 수단을 없애면 안 됩니다.

**시리즈 색을 추가·변경하려면:**

1. dataviz 스킬의 `scripts/validate_palette.js` 를 **이 앱의 표면 색으로** 실행합니다.
   ```
   node <skill>/scripts/validate_palette.js "<hex,...>" --mode light --surface "#fcfcfb" --pairs all
   node <skill>/scripts/validate_palette.js "<hex,...>" --mode dark  --surface "#1a1a19" --pairs all
   ```
2. FAIL 이 하나라도 있으면 채택하지 않습니다. WARN 은 구제 수단(레이블·표)을 명시해야 채택할 수 있습니다.
3. 결과 수치를 이 문서 §4 에 갱신합니다.

**절대 하지 않는 것:** ΔE 를 머리로 추정하기, "비슷해 보이니 괜찮다"고 판단하기, 시리즈 4개 이상을 한 차트에 넣기(3개까지만 all-pairs 통과).

## 5. 컴포넌트 규약

정의 위치: `src/components/display/` (Primitives, Table, Icon), `src/components/inputs/`, `src/components/charts/ChartChrome.tsx`.
**새 화면에서 이 프리미티브를 우회해 직접 스타일링하지 마세요.**

| 용도 | 컴포넌트 | 비고 |
|---|---|---|
| 내용 컨테이너 | `Panel` (별칭 `Card`) | hairline 1개, 그림자 없음 |
| 접히는 섹션 | `Section` | 셰브런 회전으로 상태 표시 |
| 섹션 내 하위 묶음 | `FieldGroup` | 배경만 눌러 구분 (테두리 중첩 금지) |
| 1순위 지표 | `HeroMetric` | 화면당 1개 |
| 일반 지표 | `Metric` | 테두리 없음 |
| 달성률 | `Gauge` | 100% 도달 시 체크 아이콘 동반 |
| 구성비 | `SplitBar` + `SeriesKey` | 채움 사이 2px 표면 간격 |
| 버튼 | `Button` (`primary`/`secondary`/`ghost`) | primary 는 화면당 1개 |
| 경고·안내 | `Callout` | 아이콘 필수 |
| 배지 | `StatusBadge` | 세제 상태 5종 |
| 계산식 | `FormulaPopover` | 바깥 클릭·ESC 로 닫힘 |
| 표 | `Table` 계열 | 세로줄 금지, 행 hairline만 |
| 차트 크롬 | `ChartChrome` | 축·격자·툴팁·토글 |

### 5.1 헤더
얇게(56px) 유지합니다. 액션을 나열하지 않습니다 — 공유만 노출하고 나머지는 오버플로 메뉴(`More`)로 접습니다.

### 5.2 입력
`InputShell` 이 테두리·포커스를 담당하고 안의 `input` 은 투명합니다. **단위(원·%·세)는 필드 안에** 둡니다 — 바깥에 두면 값과 단위가 한 덩어리로 읽히지 않습니다.
슬라이더는 트랙·썸을 직접 그립니다(`src/index.css`). 채워진 구간은 `--range-fill` 인라인 변수로 액센트 처리합니다.

### 5.3 표
- 세로 구분선을 긋지 않습니다. 행 hairline 과 정렬만으로 열이 읽힙니다.
- 숫자 열은 우측 정렬 + `.numeric`.
- 긴 표는 자체 영역에서 세로 스크롤하고 머리행을 `sticky` 로 고정합니다.
- 넓은 표는 `.table-scroll` 안에서만 가로 스크롤합니다. **페이지 본문이 가로로 밀리면 안 됩니다.**

### 5.4 차트
- Recharts 기본 툴팁·범례를 쓰지 않습니다 → `ChartTooltip`, `SeriesKey`.
- 격자는 가로선만, `--rule` 색. 축 눈금은 `--ink-muted` 11px.
- 선 굵기 2px, 면적 `fillOpacity` 0.28.
- 시리즈 2개 이상이면 범례가 항상 있습니다. 이중 축(dual-axis)은 **금지**입니다.
- 색은 대상(entity)을 따릅니다. 인덱스로 배정하면 항목이 사라질 때 남은 것의 색이 바뀝니다 — `PhaseTable` 의 구간 색이 이름 기반 매핑인 이유입니다.

## 6. 아이콘

`src/components/display/Icon.tsx` 의 인라인 SVG만 씁니다. 24×24 viewBox, `strokeWidth 1.75`, `currentColor`.

**텍스트 글리프(`▼ ▶ ✕ ⓘ ⚠ ▲ ƒ ✓ ↗`)를 UI 에 쓰지 마세요.** 폰트마다 자형·기준선·굵기가 달라 플랫폼별로 정렬이 흔들리고, 스크린리더가 문자로 읽습니다.
아이콘 라이브러리를 의존성으로 추가하지 않습니다 — 필요한 것만 직접 그립니다 (CLAUDE.md §2).

## 7. 모션

- 색 전환 `transition-colors`, 폭 전환 `transition-[width]` 정도. 기본 duration 유지.
- 진입 애니메이션·패럴랙스·스프링 없음. 계산기는 즉시 반응해야 하는 도구입니다.
- `prefers-reduced-motion` 은 `src/index.css` 에서 전역 차단됩니다.

## 8. "AI 티" 안티패턴 체크리스트

새 화면을 만든 뒤 아래를 훑으세요. **하나라도 해당하면 아직 덜 된 것입니다.**

- [ ] `bg-white` + `border-slate-200` + `rounded-lg` 조합이 반복되는가
- [ ] `text-xs` / `text-sm` / `text-base` 같은 Tailwind 기본 크기를 썼는가
- [ ] `blue-600`, `slate-500`, `amber-50` 처럼 팔레트 번호를 직접 썼는가
- [ ] `dark:` 변형을 컴포넌트마다 손으로 붙이고 있는가 (토큰이 이미 테마를 처리합니다)
- [ ] 모든 블록이 똑같은 무게의 카드라서 어디를 먼저 볼지 모르겠는가
- [ ] 아이콘 자리에 텍스트 글리프가 있는가
- [ ] 버튼이 3개 이상 같은 스타일로 나열되어 있는가
- [ ] 색만으로 상태·계열을 구분하고 레이블이 없는가
- [ ] Recharts·네이티브 select 의 기본 모양이 그대로 보이는가
- [ ] 그림자가 패널에 붙어 있는가
- [ ] 라벨이 값만큼 진한가

## 9. 새 화면 만들 때 절차

1. `05-ui-ux.md` 에서 그 화면의 정보구조·순서·카피 규칙을 확인합니다.
2. 이 문서의 프리미티브 표(§5)에서 쓸 컴포넌트를 고릅니다. 없으면 **새로 만들어 `src/components/` 에 넣고 이 문서에 등재**합니다 — 화면 파일 안에서 일회성으로 스타일링하지 않습니다.
3. 차트가 있으면 dataviz 스킬을 먼저 읽고, 색을 새로 쓸 경우 §4 절차를 밟습니다.
4. `npm run typecheck && npm run lint && npm run test` 를 통과시킵니다.
5. §8 체크리스트를 훑습니다.

## 10. 검증된 사실 (재확인 불필요)

- `file://` 로 연 문서에서 **인라인** `<script type="module">` 은 실행됩니다. 차단되는 것은 외부 파일을 가리키는 module script 입니다. (헤드리스 Chrome 실측)
- 단일 파일 빌드(`npm run build:local` → `dist-local/index.html`)는 `file://` 에서 전체 앱이 렌더링됩니다. 계산·차트 포함.
- 호스팅 빌드(`npm run build` → `dist/`)는 `file://` 로 **열리지 않습니다.** 절대경로·module CORS·CSP `'self'` 세 가지가 동시에 막습니다. 이는 버그가 아니라 정적 호스팅 전제입니다.
