## 1. 원안 평가

원안은 일반적인 "복리 계산기" 수준을 명확히 넘어섭니다. 특히 아래 4가지는 이 분야 계산기 대부분이 놓치는 지점을 정확히 짚었습니다.

| 원안의 강점 | 평가 |
|---|---|
| 명목/실질 금액 상시 병기 | 장기 계산기의 가장 흔한 오류를 방지. **필수 원칙으로 승격** |
| Total Return 입력 시 배당 중복 가산 방지 | 정확한 지적. 다만 해결 방식이 원안보다 복잡함 (→ §3.1) |
| 세율 하드코딩 금지 | 옳음. 구체적 구조로 확정 (→ §3.4) |
| Sequence of Returns Risk 대비 구조 설계 | 은퇴 계산의 핵심. 구조 설계 요구는 적절 |
| 결과 화면 최상단에 "현재 가치 기준 월 사용 가능액" | 사용자가 실제로 알고 싶은 지표를 정확히 특정 |

**총평:** 방향은 그대로 유지합니다. 아래는 "틀렸다"가 아니라 **이대로 구현하면 결과 숫자가 달라지거나, 사용자가 오해하거나, 구현 중에 결정을 미룰 수밖에 없는 지점**들입니다.

## 2. 반드시 보완해야 할 항목 (우선순위 순)

### 🔴 P0 — 이걸 정하지 않으면 구현이 불가능하거나 숫자가 틀립니다

#### 2.1 "안전인출률 3.5%"의 정의가 두 가지로 갈립니다

원안 2·3번 항목이 "연 3% / 3.5% / 4% 인출"을 요구하지만, 이 문장은 **서로 다른 두 전략**을 뜻할 수 있고 결과가 크게 다릅니다.

| 방식 | 정의 | 특징 |
|---|---|---|
| **A. 고정 실질 인출** (Bengen 4% 룰 원전) | 첫해에 은퇴자산 × 3.5%를 인출하고, 이후 **매년 물가상승률만큼 인출액을 증액**. 잔여자산과 무관 | 생활비가 안정적. **자산 고갈 가능** |
| **B. 고정 비율 인출** (Endowment) | 매년 **그 해 잔여자산 × 3.5%** 인출 | 절대 고갈되지 않음. **생활비가 시장에 따라 출렁임** |

원안의 "자산 보존형"은 B에 가깝고, "3.5% 인출률로 필요자산 계산"은 A를 전제합니다. **혼용하면 계산기 내부에서 모순이 발생합니다.**

**→ 보완:** 인출 전략을 명시적 선택 항목으로 승격하고 4가지를 제공. 기본값은 A(고정 실질 인출), 화면에 정의를 항상 표기.
1. 고정 실질 인출 (Bengen형) — 기본값
2. 고정 비율 인출 (자산 보존형)
3. 계획 소진형 (실질 연금 상환 방식, 목표 연령에 잔액 0)
4. 매년 재계산형 (VPW: 남은 기간·잔여자산으로 매년 재산정)

#### 2.2 인출 단계의 세금이 완전히 누락되었습니다

원안 5번은 **축적 단계** 세금만 다룹니다. 그런데 "매달 쓸 수 있는 돈"은 **세후 금액**이어야 의미가 있고, 인출 단계 세금은 계좌 유형별로 전혀 다릅니다.

- **일반계좌**: 매도 시 매매차익 과세 (국내상장 해외ETF는 배당소득 15.4%, 해외상장 ETF는 양도소득 22%·연 250만원 공제). 즉 인출액 전체가 아니라 **인출액에 포함된 차익분에만** 과세되므로 원금비율 추적이 필요합니다.
- **연금저축/IRP**: 연금소득세 3.3~5.5%, 사적연금 연 1,500만원 초과 시 종합과세 또는 16.5% 분리과세 선택. 55세 이후·10년 이상 수령 요건, 연금수령한도 존재.
- **ISA**: 만기 해지 시 순이익에서 비과세 한도 차감 후 초과분 9.9% 분리과세.

**→ 보완:** 계산 엔진에 **인출 단계 세금 모델**과 **필요 인출액 역산(gross-up)** 을 추가. 화면에는 "세전 인출액 / 세후 실수령액"을 구분 표시.

#### 2.3 은퇴 후 건강보험료가 누락되었습니다 — 실질 생활비에 큰 영향

한국에서 은퇴 후 실수령액을 좌우하는 가장 큰 변수 중 하나입니다. 직장가입자 자격을 잃으면 지역가입자로 전환되어 **소득 + 재산**에 보험료가 부과되고, 자산이 수억 원대면 피부양자 등록도 어렵습니다. 세금만 계산하고 건보료를 빼면 실수령액이 과대 계산됩니다.

**→ 보완:** 은퇴 후 고정비에 "건강보험료(추정)" 항목 추가. 정밀 부과체계 모사는 과도하므로 **① 단순 정액 입력 ② 소득 대비 요율 근사 ③ 미반영** 3가지 모드 제공, 기본값은 ②, 근거와 한계를 화면에 명시.

#### 2.4 은퇴 시점과 연금 수령 시점 사이의 "브리지 기간"이 없습니다

예: 52세 은퇴 → 국민연금 65세 수령 → **13년간은 투자자산만으로 생활**해야 합니다. 이 기간의 인출 압력이 가장 크고, 연금저축도 55세 전에는 못 씁니다. 원안은 은퇴 후를 하나의 균일 구간으로 다룹니다.

**→ 보완:** 은퇴 후를 **연령 구간별 타임라인**으로 모델링.
- 구간 1: 은퇴 ~ 55세 (일반계좌/ISA만 사용 가능)
- 구간 2: 55세 ~ 국민연금 수령 개시 (사적연금 추가)
- 구간 3: 국민연금 개시 ~ 종료 연령 (공적연금 추가, 자산 인출 감소)

각 구간의 필요 인출액이 다르게 계산되어야 하며, 결과 화면에 구간별 현금흐름 표를 제공합니다.

#### 2.5 계좌 납입한도 초과 시 자금 배분 규칙이 없습니다

원안은 계좌 유형을 "선택"하게 했지만, 실제로는 **한 계좌에 다 넣을 수 없습니다.**

| 계좌 | 연 납입한도 (2026 기준) |
|---|---|
| 연금저축 + IRP 합산 | 1,800만원 (세액공제는 900만원까지) |
| ISA | 4,000만원 (총 2억원) |
| 일반계좌 | 무제한 |

월 300만원(연 3,600만원)을 "연금저축"으로 선택하면 한도를 초과합니다.

**→ 보완:** 단일 계좌 선택 대신 **다중 계좌 포트폴리오 + 오버플로 배분** 모델 채택. 기본 우선순위: `연금저축/IRP(세액공제 한도) → ISA → 연금저축/IRP(추가) → 일반계좌`. 사용자가 순서와 금액을 직접 조정할 수 있게 하고, 한도 초과 시 자동으로 다음 계좌로 넘김.

#### 2.6 연금계좌 세액공제 환급금의 처리가 없습니다

연금저축·IRP 납입 시 최대 148.5만원(900만원 × 16.5%)을 환급받습니다. **이 돈을 재투자하는지 여부가 장기 결과를 크게 바꿉니다.** 원안에 언급이 없습니다.

**→ 보완:** "세액공제 환급금 재투자 여부" 입력 추가(기본: 재투자 ON). 재투자 시 다음 연도 납입금에 가산.

#### 2.7 계산 규약(convention)이 미정의 — 원안 32행의 요구를 확장

원안은 월초/월말만 언급했지만, 실제로 숫자를 바꾸는 규약이 더 있습니다. 아래를 **명시적으로 고정**해야 합니다.

| 규약 | 확정값 |
|---|---|
| 납입 시점 | **월초 납입**(annuity-due) 기본, 월말 토글 제공 |
| 연 → 월 수익률 변환 | **기하평균** `(1+r)^(1/12) − 1`. 단순 `r/12` 사용 금지 |
| 실질 수익률 | **Fisher 정확식** `(1+r)/(1+i) − 1`. 근사식 `r − i` 사용 금지 |
| ETF 총보수 차감 | 자산 비례 차감 → 월 배율에 `(1−TER)^(1/12)` 곱 |
| 납입금 증액 시점 | 투자 개시 후 12개월마다 (연 1회) |
| 반올림 | 중간 계산 반올림 금지, **표시 시점에만** 원 단위 반올림 |
| 물가 기준 시점 | 모든 실질금액은 **오늘(계산 실행일)** 구매력 기준 |

### 🟡 P1 — 사용자가 실제로 원하는데 원안에 없는 기능

#### 2.8 역산(목표 → 필요 납입액) 기능

원안은 전부 "정방향"(납입 → 결과) 계산입니다. 그런데 사용자의 실제 질문은 대개 역방향입니다.

**→ 보완:** 솔버 3종 추가 — ① 목표 달성에 필요한 **월 납입액** ② 필요한 **연평균 수익률** ③ 달성 가능한 **가장 이른 은퇴 나이**.

#### 2.9 퇴직금 / DC 퇴직연금 자산 누락

한국 직장인 은퇴 자산의 큰 비중입니다. 원안 입력값에 "현재 초기 투자금"만 있습니다.

**→ 보완:** 초기 자산을 계좌별로 분리 입력(일반/ISA/연금저축/IRP/DC·퇴직금). 퇴직 시 수령 예상 퇴직금은 일회성 유입 이벤트로 처리.

#### 2.10 일회성 현금흐름 이벤트

주택 구입, 자녀 학자금, 상속, 전세보증금 회수 등은 장기 계획을 완전히 바꿉니다.

**→ 보완:** `{연도, 금액, 유입/유출, 실질/명목}` 형태의 일회성 이벤트 목록 입력 (P1, 최대 10건).

#### 2.11 국민연금 입력이 "선택 항목"으로 너무 단순합니다

원안은 "국민연금 등 별도 연금소득(선택)"으로만 처리합니다. 그런데 국민연금은 ① **물가에 연동**되어 실질가치가 유지되고(사적연금은 안 됨) ② 수령 개시 연령이 출생연도별로 다르고 ③ 조기수령 감액(연 6%)·연기수령 증액(연 7.2%)이 있습니다. 단순 정액 입력은 결과를 왜곡합니다.

**→ 보완:** 국민연금 입력을 별도 섹션으로 분리 — 예상 월 수령액(현재가치), 수령 개시 연령, 조기/연기 선택, **물가연동 여부(기본 ON)**. 2026년 개혁 반영(보험료율 9.5%→2033년 13%, 소득대체율 43%).

#### 2.12 인출 순서(withdrawal sequencing) 최적화

어떤 계좌에서 먼저 빼는지에 따라 세금이 달라집니다.

**→ 보완:** 인출 우선순위를 설정 가능하게 하고, 기본값은 `일반계좌 → ISA → 연금계좌`(연금계좌를 최대한 늦게 = 과세이연 극대화). 단, 55세 이전 구간에서는 연금계좌 접근 불가 제약을 강제.

#### 2.13 Monte Carlo 스펙 미정의

원안은 "구조를 만들어달라"고만 했습니다. 나중에 붙일 때 재설계하지 않도록 스펙을 미리 확정합니다.

**→ 보완:** 수익률 분포 모델(로그정규 / 과거수익률 블록 부트스트랩 2가지), 기본 변동성 σ=15%, 시행 10,000회, Web Worker 실행, 결과 지표 = 성공확률(P(자산>0 at 종료연령)) + 백분위 경로(10/25/50/75/90) + **자산 고갈 연령 분포** + SORR 지표(초기 10년 하위 10% 경로).

### 🟢 P2 — 품질·신뢰성 관련 보완

#### 2.14 Total Return 중복 가산 방지의 올바른 해법 (원안 19행)

원안의 요구는 맞지만, "배당수익률을 더하지 않는다"만으로는 부족합니다. **일반계좌의 배당 원천징수(15.4%)를 계산하려면 총수익률 중 배당이 몇 %인지 반드시 알아야 합니다.**

**→ 보완:** 수익률 입력을 2가지 모드로 분리하고, 어느 모드든 내부적으로 `가격상승률 + 배당수익률`로 분해.
- **모드 A (Total Return, 기본)**: 총수익률 1개 입력 + 배당수익률 입력(기본 1.5%) → 가격상승률 = 총수익률 − 배당수익률. 화면에 분해 결과를 명시.
- **모드 B (분리 입력)**: 가격상승률 + 배당수익률 각각 입력 → 총수익률 = 합산.

두 모드 모두 총수익률은 절대 이중 계산되지 않으며, 모드 전환 시 값이 보존됩니다.

#### 2.15 "4% 룰"의 한국 적용 한계 고지

4% 룰은 미국 주식·채권 과거 데이터, 30년 기간, 미국 세제 기준입니다. 한국의 세제·건보료·기대수명(90세+ 가정 시 40년 이상)에는 그대로 적용되지 않습니다.

**→ 보완:** 인출률 비교 화면에 출처와 한계를 각주로 고지. 기본 권장값은 4%가 아닌 **3.5%** 로 설정.

#### 2.16 목표 달성률의 정의

"경제적 자유 목표 달성률"이 자산 기준인지 월 인출액 기준인지 원안에 없습니다.

**→ 보완:** **실질 월 인출 가능액 ÷ 목표 월 실질 생활비** 로 정의(사용자 체감과 일치). 자산 기준 비율도 보조 표시.

#### 2.17 개인정보 및 면책

소득·자산 등 민감 정보를 다룹니다.

**→ 보완:** **완전 클라이언트 사이드 처리(서버 전송 없음)** 를 아키텍처 원칙으로 확정하고 화면에 명시. 투자 권유가 아니며 세금 계산은 참고용이라는 면책 문구 상시 표시.

#### 2.18 세제 데이터의 "확정 / 개정안" 구분

조사 중 실제로 충돌하는 정보를 발견했습니다. 2026년 ISA 비과세 한도를 500만원/1,000만원으로 서술한 자료가 다수 있으나, 2026-08-03 발표된 2026 세제개편안 보도는 **"현행 일반형 200만원 / 서민형 400만원"** 을 전제로 하고 있습니다. 즉 상향안은 **아직 확정되지 않은 개정안**일 가능성이 높습니다.

**→ 보완:** 세제 데이터의 모든 항목에 `status: "확정" | "개정안" | "검증필요"` 필드를 두고, 개정안은 기본 계산에서 **제외**하되 "개정안 적용해보기" 토글로 비교 가능하게 합니다. 각 항목에 출처 URL과 기준일을 필수로 붙입니다.

#### 2.19 환율 리스크

해외 ETF 투자 시 원/달러 환율이 수익률에 직접 영향을 줍니다.

**→ 보완:** MVP에서는 "입력한 수익률은 원화 기준 수익률"이라고 **가정을 명시**하고 환율은 모델링하지 않음. 가정 패널에 명기. (P3에서 환율 시나리오 검토)

#### 2.20 비기능 요구사항 부재

**→ 보완:** 입력 검증 범위와 비현실적 입력 경고(예: 기대수익률 >15% 경고), 시나리오 저장/URL 공유, CSV·이미지 내보내기, 모바일 우선 반응형, 한국식 금액 표기(억/만원), 접근성(키보드·스크린리더·색약 대응), 계산 성능 목표(기본 계산 <50ms, MC 10,000회 <3s).
